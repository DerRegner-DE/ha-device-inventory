## Для чего нужно Управление устройствами

Умный дом растёт: роутеры, датчики, розетки, камеры, термостаты, шлюзы. Где записан серийный номер репитера, когда куплен термостат, действует ли ещё гарантия, какой выключатель перемкнут? «Управление устройствами» — это список с поиском по всем устройствам в доме, прямо в Home Assistant.

Типичные задачи:

- **Страховка** — инвентарь с серийными номерами, датами покупки, фото и чеками; при страховом случае всё под рукой.
- **Гарантия** — дата покупки и окончание гарантии для каждого устройства.
- **Обслуживание** — прошивка, IP- и MAC-адрес, сеть и интеграция на одном экране.
- **Передача, демонтаж, наследство** — список для родственников, электрика или покупателя: что работает без Home Assistant, какие выключатели перемкнуты, где лежат документы.
- **Аренда и налоги** — учёт оснащения сдаваемых квартир или устройств, используемых в бизнесе.

Приложение работает как дополнение Home Assistant с собственной базой данных, доступно на телефоне, планшете и ПК и работает без соединения; изменения синхронизируются, как только соединение восстановится.

## Установка, обновление, удаление

**Требования:** Home Assistant OS или Supervised (дополнения должны быть доступны), архитектура amd64, aarch64 (например, Raspberry Pi 4/5) или armv7, современный браузер. Камере и сканеру штрихкодов нужно зашифрованное соединение (HTTPS), см. [Камера и сканер](#камера-и-сканер).

**Установка:**

1. В Home Assistant откройте **Настройки → Дополнения** (в новых версиях **Приложения**) → **Магазин дополнений**.
2. Справа вверху меню из трёх точек → **Репозитории**.
3. Вставьте `https://github.com/DerRegner-DE/ha-device-inventory`, нажмите **Добавить**, закройте диалог.
4. Найдите в магазине **Geraeteverwaltung** (при необходимости перезагрузите страницу) → **Установить**.
5. **Запустить**, включите **Показывать на боковой панели**, затем **Открыть веб-интерфейс**.

**Обновление:** Доступное обновление Home Assistant показывает в разделе *Настройки → Дополнения → Geräteverwaltung* (и в уведомлениях). Нажмите **Обновить**; параметр *Создать резервную копию перед обновлением* рекомендуется, так как обновления могут расширять базу данных. Также можно включить *Автоматическое обновление*. Что нового, описано в журнале изменений (Changelog) дополнения. После обновления загляните в раздел «После обновления» быстрого старта.

**Удаление:** *Настройки → Дополнения → Geräteverwaltung → Удалить*. При этом Home Assistant удаляет каталог данных дополнения вместе с базой данных, фото и лицензией. Заранее сохраните данные: *Настройки → Экспорт данных* (JSON, Excel, PDF) или резервная копия Home Assistant, включающая дополнение.

## Быстрый старт за 5 шагов

1. **Установите дополнение** через URL магазина дополнений Home Assistant (см. README в репозитории GitHub). После установки «Управление устройствами» появится как пункт в боковой панели HA.
2. **Активируйте лицензию Pro** в разделе *Настройки → Лицензия*. Без лицензии можно вести до 50 устройств, интерфейс тогда на английском — всё остальное (многоязычность, Excel, MQTT, камера, штрихкоды, документы) входит в Pro.
3. **Импортируйте устройства HA** в разделе *Настройки → Импорт Home Assistant → Импортировать устройства HA*. В больших системах (300+) импорт может занять минуту; он идёт в фоне с индикатором прогресса. Переносятся название, производитель, модель, прошивка, помещение и этаж, интеграция, сеть и — начиная с 3.1.0 — серийный номер, MAC-адрес и питание (батарея/аккумулятор), если они известны Home Assistant. Повторный импорт не создаёт дубликатов и у существующих устройств дописывает серийный номер и MAC только в пустые поля.
4. **Дополнительно: включите MQTT-Discovery** в разделе *Настройки → Интеграция Home Assistant → Публиковать устройства в HA* — когда это имеет смысл, описано в главе [Интеграция Home Assistant](#интеграция-home-assistant-mqtt-discovery).
5. **Дополните первые устройства**: нажмите на устройство в списке, затем *Редактировать*, и укажите как минимум дату покупки, окончание гарантии и цену покупки. Добавьте фото устройства и фото места установки, загрузите чеки как документы — документация для страховки готова.

### После обновления до 3.1.0

Один раз в таком порядке:

1. *Настройки → Импорт Home Assistant → Импортировать устройства HA* — дописывает серийный номер и MAC у существующих устройств и снимает неверные привязки к роутеру (см. [Многоканальные устройства](#многоканальные-устройства-parent-child)).
2. *Настройки → Возможные дубликаты* — проверьте и объедините дублирующиеся устройства (см. [Дублирующиеся устройства](#объединение-дублирующихся-устройств)).
3. *Настройки → Перекатегоризировать устройства → Предпросмотр и выбор* — после 3.1.0 предпросмотр показывает заметно больше предложений, чем раньше, потому что распознавание впервые видит классы устройств из Home Assistant. Кроме того, дописывается питание. Сначала просмотрите предпросмотр, снимите отметки с отдельных строк, затем примените. Всё можно отменить через снимок и историю устройства.

## Добавление устройств

Новые устройства добавляются через **Добавить** в нижней панели, существующие — через страницу устройства → **Редактировать**. Обязательны только *Тип устройства* и *Название*. Форма разбита на разделы, которые можно сворачивать и разворачивать:

| Раздел | Поля |
|---|---|
| Основные данные | Тип устройства, Название, Модель, Производитель, Прошивка |
| Местоположение | Зона из Home Assistant (этаж определяется по ней) |
| Сеть и Питание | Сеть, Питание, IP-адрес, MAC-адрес |
| Детали | Серийный номер, AIN / Артикул, Дата покупки, Гарантия до |
| Home Assistant | Интеграция, Entity ID, Device ID |
| Заметки | Функция, Примечания, «Работает без Home Assistant?», «Настенный выключатель перемкнут?», Внешняя ссылка |

При редактировании ниже появляются **Фото установки** (с подписью, например «за крышкой слева вверху») и **Документы** (счёт, инструкция — файлом или ссылкой). Фото устройства можно прикрепить вверху формы с камеры или из файла. Каждое изменение попадает в *История изменений* на странице устройства и там же отменяется по отдельности.

**Интеграция** — свободное поле: список подсказок содержит распространённые интеграции и все, что встречаются в Вашем инвентаре; любое другое значение можно ввести вручную.

**Значения для выбора:**

- *Сеть:* WiFi, LAN, Zigbee, Z-Wave, Bluetooth, Thread/Matter, DECT, Powerline, HomeMatic RF, KNX, Modbus, 1-Wire, RS-232, EnOcean, USB
- *Питание:* Блок питания, 230В, Батарея, Аккумулятор, USB, PoE, Солнечная, Высокое напряжение
- *Типы устройств (32):* Роутер, Репитер, Powerline, DECT репитер, Розетка, Выключатель, Лампочка, Актуатор/Реле, Переключатель/Кнопка, Роллеты, Термостат, Контроллер/Шлюз, Камера, Дверной звонок, Гонг, Замок, Сигнализация, Голосовой ассистент, Smart TV, Стриминг, Дисплей/Панель, Планшет, Колонка, Бытовая техника, Робот-газонокосилка, Полив, Вентилятор, Пульт управления, Принтер, Датчик, Смартфон, Прочее

Собственные типы устройств создаются в разделе *Настройки → Управление категориями*; после этого они доступны во всех списках выбора, в массовом редактировании и как вкладки фильтра.

### Камера и сканер

С Pro можно делать фото прямо в приложении и сканировать QR-/штрихкоды. MAC-адрес в коде распознаётся и записывается, иначе содержимое попадает в форму как серийный номер; структурированные коды (например, `SN:…|MAC:…|MODEL:…`) заполняют сразу несколько полей. Браузеры дают доступ к камере только через зашифрованное соединение: через Home Assistant Cloud (Nabu Casa), собственный сертификат или обратный прокси. При доступе через `http://<IP>:8123` можно выбрать существующее изображение, но не камеру.

## Интеграция Home Assistant (MQTT-Discovery)

Самый частый вопрос на форуме. Мы объясняем, **что** делает переключатель, **когда** он полезен и **как** его снова чисто убрать.

### Что происходит при включении?

Если Вы включаете *Публиковать устройства в HA*, дополнение публикует **до 6 записей MQTT-Discovery на каждое устройство инвентаря** на брокере, заданном в настройках дополнения (по умолчанию: `core-mosquitto`):

| Тип объекта | Содержимое | Пример |
|------------|--------|----------|
| Сенсор `*_warranty` | дата ISO, до которой действует гарантия | `2027-03-15` |
| Сенсор `*_warranty_days` | оставшиеся дни числом | `123` |
| Сенсор `*_purchase` | дата покупки | `2024-09-12` |
| Сенсор `*_type` | тип устройства | `Router` |
| Сенсор `*_location` | местоположение | `Büro OG` |
| Бинарный сенсор `*_warranty_active` | `on`, пока действует гарантия | `on` / `off` |

Эти объекты появляются в HA в разделе *Настройки → Устройства и службы → MQTT*, отдельная карточка устройства на каждую запись инвентаря.

**Начиная с 3.1.0** сенсор `*_type` дополнительно несёт заполненные данные как атрибуты: местоположение, серийный номер, питание, функция, примечания, «Работает без HA» и «Настенный выключатель перемкнут» вместе с примечаниями, внешняя ссылка, а также число фото и фото места установки. Пустые значения отсутствуют. В автоматизациях доступны, например, через `state_attr('sensor.landroid_s300_device_type', 'seriennummer')`.

**Обратно в приложение:** На странице устройства в HA у каждого так опубликованного устройства есть ссылка **Перейти**. Она открывает это устройство прямо в «Управлении устройствами». Для устройств других интеграций (например, исходная страница устройства Shelly) дополнение не может задать ссылку — там путь только через MQTT-карточку записи инвентаря.

### Данные для входа в MQTT-брокер

**Зачем:** Для публикации «Управление устройствами» должно войти в MQTT-брокер; дополнение Mosquitto допускает только авторизованных участников. Без MQTT приложение в остальном работает полностью — затронуты только сенсоры в HA и ссылка *Перейти*.

Дополнение сначала запрашивает данные для входа у Supervisor. Если дополнение Mosquitto предоставляет их там, ничего вводить не нужно. Если же проверка в разделе *Настройки → Интеграция Home Assistant → Проверить соединение MQTT* сообщает **«Not authorized»** (код 135), дополнению нужен пользователь. Проще всего — отдельный пользователь Home Assistant; дополнение Mosquitto принимает любого пользователя HA:

1. В Home Assistant слева внизу **Настройки** → **Люди** → вверху откройте вкладку **Пользователи**. Если вкладки нет: нажмите слева внизу на своё имя и включите **Расширенный режим**.
2. Справа внизу **Добавить пользователя**. Отображаемое имя и имя пользователя, например `geraeteverwaltung`, задайте пароль.
3. Включите **«Может входить только из локальной сети»**, **«Администратор»** оставьте выключенным. **Создать**.
4. **Настройки** → **Дополнения** (в новых версиях **Приложения**) → **Geräteverwaltung** → вкладка **Конфигурация**.
5. В **mqtt_user** введите имя пользователя, в **mqtt_password** — пароль. **Сохранить**, перезапустите дополнение.
6. В «Управлении устройствами» нажмите *Проверить соединение MQTT* — теперь должно появиться «OK».

Почему отдельный пользователь, а не Ваша учётная запись: у него нет прав администратора, он входит только из домашней сети, а в конфигурации дополнения хранится его пароль, а не Ваш. Когда он больше не нужен, его можно удалить, ничего больше не затрагивая.

### Когда это полезно?

- **Напоминания о гарантии**: автоматизация HA на бинарный сенсор `*_warranty_active`, которая уведомляет за 30 дней до окончания.
- **Карточки панели**: «Все устройства на гарантии», «Устройства, гарантия которых скоро истекает», с сортировкой по `*_warranty_days`.
- **Статистика инвентаря** на панели HA, без необходимости открывать само «Управление устройствами».

**Не** полезно, если Вы используете дополнение только как инструмент документации — тогда оно лишь создаёт карточки в HA, на которые никто не смотрит.

### Очистка, если функция больше не нужна

Частый вопрос: *«Как удалить все MQTT-топики, если я выключаю дополнение?»*

По умолчанию retained-топики MQTT **остаются** на брокере, даже если Вы выключите переключатель. Это особенность MQTT-Discovery (HA не удаляет retained-сообщения, записанные другим отправителем). Три способа чистой очистки:

1. **(Рекомендуется) Очистить осиротевшие записи**: В блоке настроек *Интеграция Home Assistant* начиная с v2.6.0 есть кнопка **«Очистить осиротевшие записи»**. Она удаляет все retained-топики для устройств инвентаря, которые Вы уже удалили в «Управлении устройствами». Активные устройства не затрагиваются. Безопасно как регулярное действие.

2. **Удалить все записи MQTT**: Рядом кнопка **«Удалить все записи MQTT»** (красная). С подтверждением. Удаляет **каждое** сообщение Discovery, опубликованное дополнением, в том числе для устройств, которые ещё есть в инвентаре. Разумный последний шаг перед окончательным отключением MQTT-Discovery.

3. **Вручную через MQTT Explorer**: топики `geraeteverwaltung/#` и `homeassistant/+/geraeteverwaltung/+/config` — для каждого топика правый клик → «Delete topic». Единственный способ для установленных версий без v2.6.0.

### Устройства остаются в HA после удаления в дополнении

До v2.5.3 была ошибка, из-за которой очистка MQTT при удалении отдельных устройств пропускалась — топики Discovery оставались, хотя дополнение должно было отправить сигнал «удалить это устройство». Начиная с v2.5.3 очистка отдельного устройства снова работает надёжно. Для существующих остатков: один клик на *Очистить осиротевшие записи* убирает их.

## Многоканальные устройства (Parent-Child)

Примеры: Shelly 2PM (два канала розетки в одном корпусе), хабы Tuya, USB-хабы, Bosch SHC с подключёнными термостатами. Для таких систем HA часто создаёт несколько устройств (основное устройство + по одному подустройству на канал/датчик) и связывает их через `via_device_id`.

### Что из этого делает «Управление устройствами»

- При импорте HA значение `via_device_id` анализируется и сохраняется в инвентаре как `parent_uuid`.
- На странице подустройства вверху находится блок **«Часть: …»** с переходом к основному устройству по клику.
- На странице основного устройства находится блок **«Подустройства (N)»** со списком всех дочерних устройств.
- Если в подустройстве нажать **Назад**, Вы вернётесь к основному устройству, а не в общий список.

### Скрытие подустройств

В многоканальных системах список быстро разрастается — три строки на одно физическое устройство. В списке справа от сортировки есть кнопка **«Только основные»**. Когда она активна, подустройства скрыты, а надпись кнопки показывает число скрытых дочерних устройств. Фильтр сохраняется в течение сеанса.

**Роутеры не являются основным устройством (начиная с 3.1.0):** FRITZ!Box и UPnP сообщают в Home Assistant, что *каждое* устройство в сети подключено к ним. Раньше импорт делал из этого «Часть FRITZ!Box» — звонок, робот-газонокосилка и телефоны тогда пропадали в фильтре *Только основные*. Такие привязки к роутеру импорт больше не переносит, существующие снимает при следующем запуске. Настоящие центральные устройства, такие как координатор Zigbee, Bosch Smart Home Controller или HomematicIP Access Point, остаются основным устройством для своих устройств. Если уже открытый браузер после этого ещё показывает старую привязку: *Настройки → Очистить локальный кеш → Очистить кеш*.

**Маршрутизирующие хабы не скрываются:** HA задаёт `via_device_id` и для устройств, подключённых через мост (мост Zigbee2MQTT → Hue/IKEA/Aqara, координатор ZHA → оконечные устройства, стик Z-Wave JS → оконечные устройства, сервер Matter → оконечные устройства). Эти «дочерние» устройства — отдельное оборудование, программный только мост. Поэтому фильтр обрабатывает устройства с интеграцией `mqtt`, `zha`, `zwave_js` или `matter` как основные — иначе фильтр основных устройств скрыл бы настоящие лампы и оставил бы только мост.

### Применение изменений ко всем дочерним устройствам

При редактировании основного устройства с подустройствами в конце формы появляется флажок **«Применить также к N дочерним устройствам»**. Если он включён, при сохранении *помимо* основного устройства на все дочерние устройства массово переносятся следующие поля:

- Производитель
- Дата покупки
- Гарантия до
- Питание
- AIN / Артикул

**Не** наследуются поля, зависящие от канала: название, серийный номер, MAC, IP, местоположение, идентификаторы Home Assistant.

## Объединение дублирующихся устройств

*Новое в 3.1.0.* Начиная с HA 2026.8 Home Assistant часто создаёт для одного физического устройства несколько записей: Shelly через его собственную интеграцию и ещё раз через FRITZ!Box; при нескольких FRITZ!Box в mesh-сети — даже по одному разу на каждую. В инвентаре устройство тогда появлялось несколько раз.

**При импорте** приложение автоматически объединяет записи с одинаковым MAC- или Zigbee-адресом из разных интеграций или конфигураций в одно устройство. Остаётся запись той интеграции, которая управляет устройством (Shelly, Ring, Bosch …), а не роутера. Двойник запоминается и при следующем импорте больше не создаётся.

**Устройства, уже импортированные дважды** (из версий до 3.1.0):

1. Раскройте *Настройки → Возможные дубликаты*, нажмите **Найти дубликаты**.
2. Список показывает группы с одинаковым MAC-адресом. Верхнее устройство каждой группы — предложение, оно остаётся.
3. Кнопка **→ в «Название целевого устройства»** в строке объединяет это одно устройство — или **Применить все предложения** (нажать дважды для подтверждения) для всех групп сразу.

**Вручную**, для устройств без общего идентификатора: на странице устройства **Объединить с другим устройством …**, найдите и выберите целевое устройство, **Объединить**.

Что происходит при объединении:

- Целевое устройство сохраняет все свои данные. Пустые поля приложение заполняет из другого устройства, примечания добавляются.
- Фото, фото места установки, документы, история изменений и подустройства переходят к целевому устройству.
- Другое устройство попадает в корзину. Перед этим приложение создаёт снимок базы данных — через *Настройки → Снимки базы данных* всё можно вернуть.

## Страховка и наследство — типичные сценарии

### Страховка

Шаблон *Страховка* в экспорте PDF/Excel автоматически выбирает поля, которые обычно нужны страховщику:

- №, Тип, Название, Модель, Производитель
- Серийный №, AIN / Артикул
- Дата покупки, Гарантия до, Местоположение, Заметки

Порядок действий:

1. Для каждого ценного устройства: сделайте фото, загрузите чек как документ, укажите в примечаниях цену покупки и при необходимости заметку для страховки.
2. Раз в год: *Настройки → Экспорт PDF / Excel → шаблон Страховка*. PDF содержит таблицу и (очень длинные заметки обрезаются на 1000 символах со ссылкой на экспорт Excel) раздел с деталями по каждому устройству.
3. Дополнительно Excel, если страховщик обрабатывает данные дальше — Excel хранит примечания полной длины в одной ячейке.

### Наследство

Шаблон *Наследство* предназначен для родственников — что это, где стоит, есть ли ещё гарантия, где лежат документы, работает ли без HA:

- №, Тип, Название, Производитель, Модель, Серийный №, AIN / Артикул
- Дата покупки, Гарантия до
- Местоположение, Этаж
- Работает без HA + примечание
- Внешняя ссылка
- Функция, Заметки

Сетевые детали (MAC, IP, прошивка, интеграция) начиная с 3.0.0 намеренно исключены — наследникам они не нужны и только занимают ширину столбцов.

### Передача другому человеку (демонтаж/электрик)

*Новое в 3.0.0.* Суть: однажды перед системой окажется другой человек — родственники, электрик, покупатель. Этот человек не знает ни Home Assistant, ни истории дома.

Для этого у каждого устройства есть два поля в самом низу формы редактирования, в разделе *Заметки*:

**«Работает без Home Assistant?»** — три варианта: *Неизвестно* (по умолчанию, ничего не выводится), *Да, работает без HA*, *Нет, нужен HA*. При *Да* или *Нет* ниже появляется поле примечания для пояснения простыми словами: «выключатель прямо на стене», «термостат можно настроить на самом устройстве», «без HA управлять невозможно».

**«Настенный выключатель перемкнут?»** (*новое в 3.1.0*) — самый важный пункт для демонтажа: если для этого устройства был перемкнут выключатель света, после демонтажа лампа иначе не будет работать. Три варианта (*Неизвестно*, *Да, выключатель перемкнут или отвязан*, *Нет*) и поле примечания: какой выключатель, какая коробка — или какая настройка, ведь часто ничего не перемыкали, а перенастроили актор (например, Shelly в режиме «detached»). Отображается на странице устройства в той же карточке, что и «Зависимость от Home Assistant».

**«Внешняя ссылка»** — ссылка на другую систему: документ в Paperless-ngx, страница руководства производителя, запись в собственной вики. Ссылка отображается на странице устройства и открывается в новом окне. Достаточно простого имени вроде `paperless.local/x`, `https://` добавляется автоматически.

Шаблон экспорта **«Демонтаж/электрик»** (Экспорт → выбрать шаблон) превращает это в лист, который кладут в щитовую:

- №, Тип, Название, Производитель, Модель
- Местоположение, Этаж
- Сеть, Питание
- Работает без HA + примечание
- Выключатель перемкнут + примечание
- Внешняя ссылка
- Функция, Заметки

Намеренно **без** серийных номеров, дат покупки и гарантии: этот список может открыто лежать в коридоре, а шаблоны «Страховка» и «Наследство» содержат полные данные.

Столбец *Интеграция* начиная с 3.0.0 исключён — `fritz` или `bosch_shc` относятся к внутренностям Home Assistant и ничего не говорят мастеру.

Шаблон **«Аварийная папка»** (*новое в 3.1.0*) — это папка для электрощитка: для электрика, соседа или маклера, которого родственники позовут в экстренной ситуации. Устройство, этаж и местоположение, производитель, модель, серийный номер, питание, работа без HA, перемкнутые выключатели, дата покупки, гарантия, ссылка на инструкцию, функция и примечания. Без сетевых деталей. Пароли сюда не относятся — приложение их принципиально не хранит; достаточно указать в примечаниях, где лежат данные для входа (менеджер паролей, папка).

**Все шаблоны в сравнении:**

| Шаблон | Для кого | Содержит |
|---|---|---|
| Страховка | Сотрудник страховой при страховом случае | Устройство, серийный номер, дата покупки, гарантия, местоположение, ссылка на счёт |
| Демонтаж/электрик | Мастер на месте | Устройство, местоположение, сеть, питание, работа без HA, перемкнутые выключатели, ссылка — без данных о покупке |
| Наследство | Родственники | Устройство, серийный номер, дата покупки, гарантия, местоположение, работа без HA, ссылка |
| Аварийная папка | Помощник, которого зовут родственники | Устройство, местоположение, серийный номер, питание, работа без HA, перемкнутые выключатели, дата покупки, гарантия, ссылка |

В PDF все шаблоны дают компактную таблицу в альбомной ориентации, около десяти страниц на 300 устройств. Страницы с деталями по каждому устройству создаются только тогда, когда Вы составляете поля вручную, а не выбираете шаблон. Собственный выбор полей приложение начиная с 3.1.0 сохраняет на сервере — он действует и на телефоне, и после очистки данных браузера.

**Порядок** (*новое в 3.1.0*): В диалоге экспорта можно выбрать между *По категориям* (прежнее поведение) и **Этаж › Место › Название**. Для листка в электрощитке правильный второй вариант: кто стоит перед щитком, ищет по помещению, а не по названию устройства. В Excel он выводится сплошной таблицей без промежуточных строк категорий, которую можно свободно сортировать и фильтровать.

**Изображения в PDF** (*новое в 3.1.0*): В разделе *Изображения в PDF* можно добавить **Фото места установки** и **Фото устройств и документы-изображения**. Изображения располагаются в приложении с изображениями в конце PDF; в списке столбец *Images* у каждого устройства показывает ссылку (B1, B2 …). Изображение, привязанное к нескольким устройствам, появляется только один раз, со всеми связанными устройствами. Excel изображений не содержит.

## Фильтры, поиск и сортировка

- **Поиск** вверху ищет по названию, модели, производителю, местоположению, MAC, IP, серийному номеру, интеграции, функции и типу.
- **Чипы категорий** под поиском: встроенные категории — только если в них есть хотя бы 1 устройство; собственные категории (из *Управление категориями*) начиная с 3.1.0 — всегда, как и вручную введённые типы. Клик переключает между *активен* и *выключен*. Активный фильтр остаётся видимым, даже если последнее устройство этой категории исчезло, — чтобы его можно было снять.
- **Превью фото**: если у устройства есть фото, список показывает его как небольшое превью (начиная с 3.1.0).
- **Кольцевые диаграммы** и **списки Топ 10** на панели кликабельны — клик по столбцу производителя устанавливает фильтр по производителю и переходит в список устройств.
- **Чипы фильтров** над списком (например, «По производителю: BOSCH ×») показывают активный фильтр, крестик снимает его.
- **Сортировка**: выпадающий список справа. Варианты: Недавно изменённые (по умолчанию), Имя А→Я/Я→А, Тип, Производитель, Местоположение, Гарантия скоро истечёт (ближайшее окончание первым). Выбор сохраняется в течение сеанса.
- **Переключатель «Только основные»**: скрывает дочерние устройства (см. главу о многоканальных устройствах).

## Корзина и снимки базы данных

### Корзина

- При удалении устройства удаляются *мягко*: их можно восстановить в течение 30 дней в разделе *Настройки → Корзина*.
- Два режима восстановления: по одной записи (кнопка в строке) или массово («Восстановить N» справа вверху после выбора).
- *Удалить навсегда* удаляет устройство вместе со связанными фото.
- Кнопка *Все устройства в корзину* (настройки, в самом низу) задумана как последняя кнопка сброса — перемещает весь инвентарь в корзину со снимком.

### Снимки базы данных

- Перед каждым массовым действием (bulk-delete-all, recategorize, bulk-update) автоматически создаётся снимок базы данных SQLite.
- Список в разделе *Настройки → Снимки базы данных*. Для каждой записи: имя файла, операция, дата, размер.
- *Восстановить* перезаписывает текущую БД снимком — «отмена последнего действия».

## Частые вопросы (FAQ)

### «Моё дополнение показывает 1500 устройств, а у меня их только 200.»

До v2.5.2 импорт HA выполнялся несколько раз, пока был активен MQTT-Discovery. Импорт тогда забирал обратно устройства, опубликованные самим дополнением, — число устройств в инвентаре удваивалось с каждым импортом. Решение:

1. Обновите как минимум до v2.5.2.
2. Серверный вызов `POST /api/ha/cleanup-self-imports` перемещает дубликаты в корзину. Кнопки для этого в интерфейсе нет — если Вы не хотите отправлять вызов сами, создайте issue или напишите на support@derregner.info.
3. Через 30 дней они исчезнут. Если спешите: очистите корзину.

### «Я нажимаю „Загрузить документ“ и попадаю на страницу устройства, но ничего не загружено.»

Ошибка до v2.5.3. Исправлена начиная с v2.6.0 (`type="button"` у кнопок, иначе они отправляют окружающую форму). Обновите дополнение.

### «При нажатии „Показать в HA“ открывается браузер, и мне нужно снова входить в HA.»

Это касалось приложения HA Companion на телефоне до v2.5.3. Начиная с v2.6.0 дополнение распознаёт Companion по User-Agent и переходит внутри веб-представления приложения — возврат системной кнопкой «Назад» или жестом.

### «Экспорт PDF ломает макет у устройства с длинными заметками.»

Ошибка до v2.5.3 (fpdf2 + собственный заголовок + разрыв страницы в multi_cell). Начиная с v2.6.0 заметки в разделе деталей обрезаются на 1000 символах с примечанием «... — full text in Excel export». Excel хранит полный текст в одной ячейке без проблем с макетом.

### «Где хранится лицензионный ключ? Что происходит при обновлении дополнения?»

Лицензия хранится в папке данных дополнения как `license.json` (управляется HA). Обновления дополнения её сохраняют. Переустановка = нужно ввести ключ заново.

### «Какие языки?»

DE, EN, ES, FR, RU. Переключение в настройках. Тариф Free ограничен EN — Pro открывает все языки.

## Устранение проблем

### Браузер блокирует экспорт («Небезопасная загрузка заблокирована»)

Это происходит, если Вы открываете Home Assistant по незашифрованному адресу, то есть `http://<IP>:8123`. Браузеры больше не скачивают файлы с таких страниц без запроса. К приложению это не относится — экспорт создаётся и отдаётся корректно.

**Как получить файл:** В разделе загрузок браузера нажмите **Сохранить**. Файл полный и неизменённый.

**Как убрать запрос навсегда:** Открывайте Home Assistant через зашифрованное соединение — через Home Assistant Cloud (Nabu Casa), через собственный сертификат с Duck DNS и Let's Encrypt или через обратный прокси. После этого проблема больше не возникает.

### Где хранятся мои данные и как их сохранить?

Всё, что сохраняет приложение, находится в каталоге данных дополнения:

| Что | Где |
|---|---|
| База данных со всеми устройствами | `/data/db/geraeteverwaltung.db` |
| Фото и фото места установки | `/data/photos/` |
| Лицензионный ключ | `/data/db/license.json` |

**Сохранять** вручную ничего не нужно: резервная копия Home Assistant полностью включает каталог данных дополнения. Если Вы хотите дополнительно хранить список устройств вне HA, используйте *Настройки → Экспорт данных → Экспорт JSON* или создайте снимок.

**Не** записывайте ничего в базу данных, пока дополнение работает. Если открыть и изменить её через Samba или SSH, файл может повредиться — приложение держит его открытым. Для просмотра сначала остановите дополнение.

### Не удаётся подключиться к MQTT

В разделе *Настройки → Интеграция Home Assistant* есть кнопка **«Проверить соединение MQTT»**. Она возвращает конкретное сообщение об ошибке с подсказкой в зависимости от кода ошибки:

- **Код 4 / 5 / 135 (вход отклонён, «Not authorized»)**: данные для входа отсутствуют или неверны. Пошагово в разделе [Данные для входа в MQTT-брокер](#данные-для-входа-в-mqtt-брокер).
- **Соединение отклонено**: запущен ли брокер Mosquitto? Правильный ли порт (1883 без шифрования, 8883 TLS)?
- **Недоступен / тайм-аут**: правильны ли hostname/IP? Для внешнего брокера: сеть HA должна иметь доступ к брокеру.
- **Ошибка DNS**: проверьте поле `mqtt_host` в настройках дополнения.

### Импорт HA выдаёт 502 Bad Gateway

Ошибка до v2.5.2 — импорт длился дольше, чем HTTP-тайм-аут HA Ingress. Начиная с v2.5.3 импорт идёт в фоне с опросом прогресса, тайм-аута больше нет.

### Диагностический отчёт для GitHub Issue

*Настройки → Поддержка и диагностика* формирует отчёт с версией дополнения, архитектурой, версией Python, статусом MQTT (без данных для входа), количеством устройств и последними 200 строками журнала. Пароли, токены, IP-адреса и e-mail удаляются автоматически. Отправьте по клику или скопируйте в буфер обмена.
